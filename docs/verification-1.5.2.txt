Handwriting / OCR boundary
--------------------------
This release does not claim millisecond handwriting recognition. The 1.3
benchmark remains the latest measured result: ~1,490 ms cold and ~567 ms warm
for the offline fallback; 600/480 px downscaling misread "ПО" as "ПС". The
online path can be faster when available, but it is network-dependent. The
1.5 work focused on the bundled TTS and release packaging; handwriting was not
rewritten.

Source assets
-------------

checkout must run:
    npm install
    npm run tts:prepare

from the public mirror, verifying SHA-256

1.5.2 note
----------
1.5.2 adds a local handwriting-result cache and reuses Tesseract worker
parameters. The cache is keyed by the exact rounded stroke geometry plus the
canvas size, is memory + localStorage backed, LRU-capped at 160 entries, and
is only populated by successful recognition.

Measured in the Vite dev server with WebKit/Playwright, offline handwriting,
after the Tesseract Russian worker was preloaded:
- warm-1 (new strokes): 462 ms, source offline, candidates ["ПО"].
- warm-2 (same strokes after clearing the canvas): 16 ms, status
  "本地缓存命中，可点选其他候选", same candidates.
The 16 ms is a true cache hit, including the zero-delay scheduler and React
state update. A production `vite preview` run of the built dist repeated it at
450 ms / 14 ms with the same `ПО` candidates. It is not a new-character
recognition time.

Tesseract is still the first-pass engine for unseen handwriting; a warm new
word remains roughly 0.46 s and a cold first use roughly 1.5 s. No claim is
made that arbitrary new handwriting is millisecond-level.
