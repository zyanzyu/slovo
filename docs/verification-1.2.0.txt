## 2. 架构与共用部分

```text
src/ + public/                 共用 React 前端、数据模型、SRS、OCR、导入
        │
        ├── dist/ ───────────── PWA（离线 + 可安装）
        ├── Electron 31 + HTTP server ── Windows / Linux
        └── Android WebView + 内置 HTTP server ── APK
```

- 共用数据：`localStorage` 键 `slovo.store.v1`；JSON 备份导入/导出。
- 共用学习逻辑：主动回忆、四档评分、答错重排、SM-2 思路间隔重复。
- 共用输入：拍照、照片 OCR、TXT/MD/CSV/TSV/JSON/DOCX/XLSX/XLS/PDF 文本层/HTML、粘贴文字。
- 共用手写：在线代理 + 本地 Tesseract 回退；失败可切键盘。
- 共用自适应：CSS 变量字号、320–1280px 断点；Android 额外用 WebView `textZoom`。

### 3.4 Android

```bash
bash android/build-apk.sh
```

- `aapt`：`versionCode=4`、`versionName=1.2.0`、`minSdk 26`、`targetSdk 28`。
- `javac` / R8 / D8：`classes.dex` 生成。
- `zipalign` + `apksigner`：v2/v3 签名有效，v1 为 false（minSdk 26 可接受）。
- APK 内含：`assets/www/index.html`、hashed 前端资源、`classes.dex`、`sw.js`（`slovo-v5`）、OCR 模型。
- 原生桥：文件/相机选择、TTS、备份保存、`setTextZoom`、手写代理、`/api/health`。

> 本容器没有可用的 ADB/Shizuku 安装通道，因此未执行 Android 真机安装；APK 已通过构建、签名和内容检查，并导出到手机 Download/DSHA 供手动安装。

### 3.5 桌面

- Linux arm64：1.2.0 真实启动 Electron 31，窗口 820×900，`/api/health` 返回 `{"ok":true,"platform":"linux"}`，Service Worker 关闭；首页、词库、导入导航 smoke 全部通过。
- 桌面缩放：用 X11 XTest 发真实 `Ctrl+=`，页面 `innerWidth` 从 820 变 683、`devicePixelRatio` 变 1.2，`window-state.json` 写入 `"zoom":1.2`；`Ctrl+0` 复位到 820 / 1.0。Playwright CDP 注入按键不会触发 Electron `before-input-event`，因此没有用它冒充快捷键验证。
- 820 宽 + 1.32 倍字号：`--font-scale=1.32`，正文 19.8px，页面无横向溢出。
- Linux x64 / Windows x64：归档结构、`Slovo`/`Slovo-bin`/`Slovo.exe`、`dist/sw.js` 已检查；当前容器是 aarch64 Linux，无法执行 Windows PE 和 Linux x64 Electron。

## 4. 安装/运行

### Android

1. 把 `slovo-1.2.0.apk` 放到手机。
2. 在文件管理器中点开，允许“安装未知应用”。
3. 如已安装旧版，因 `versionCode=4` 可直接覆盖；遇到签名冲突先卸载旧调试包。
4. 首次手写/OCR 会加载本地模型，稍等几秒。

### Windows

1. 解压 `slovo-1.2.0-windows-x64.zip`。
2. 进入 `Slovo-win32-x64`，双击 `Slovo.exe`。
3. 未签名，SmartScreen 选择“更多信息 → 仍要运行”。

### Linux

```bash
tar -xzf slovo-1.2.0-linux-x64.tar.gz
./Slovo-linux-x64/Slovo
```

arm64 包把目录换成 `Slovo-linux-arm64`。

### PWA

```bash
npm install
npm run build
npm start
```

打开 `http://127.0.0.1:4173`，浏览器可安装到主屏幕。

## 5. 已知限制

- Google Input Tools 在当前网络不可达；在线手写未能实测成功。静态 PWA 会先探测 `/api/health`，不可用就直接走离线 Tesseract；Android/桌面本地服务器可用时才尝试在线。
- 离线手写对印刷体单词可用，连笔草写准确率有限；识别失败有键盘入口。
- OCR 仍可能把“猫”读成“猜”；导入预览可修改后再落库。
- Android 朗读依赖系统是否安装俄语 TTS；没有时听写自动降级为中文提示。
- Windows/Linux x64 未在对应真机启动；Linux arm64 已真实启动。
- Android APK 为 debug 签名，适合个人安装测试；上架需自行用 release keystore 重签。
- 在线手写会把笔画坐标发送到 Google Input Tools；可在设置关闭，只用离线识别。
